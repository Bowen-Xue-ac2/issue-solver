## 已完成的基础验证

- `python3 -m unittest discover -s tests -v`：7 项通过。编写实现前同一套测试
  有 3 项因 CLI 不存在而失败；覆盖可携带安装、拒绝覆盖、符号链接保留、
  显式目标要求、无效目录、多目录发现，以及工具缺失/不执行。
- 随后修正“不执行工具”测试中的探针，改用 shell 内建 `printf`，避免空 PATH
  让外部 `touch` 自身失效。该项单独重跑通过；生产 helper 未变化，其他结果复用。
- 本机 skill-creator 的 `quick_validate.py skills/issue-solver`：`Skill is valid!`。
- 五类样例的编写前基线：bug、CI、SQLi 各以 exit 1 失败；参数绑定的误报样例
  以 exit 0 通过。SQLi 同时暴露注入和合法带引号输入失败，不能只封堵测试 payload。
- 所选外部来源的不可变 SHA、技能路径与许可文件实际读取核验；仅保存引用，
  没有 vendor 第三方技能正文。

## 覆盖边界

这是一个独立消费者在本地合成 fixture 上的应用试验，不是通用成功率测量。
包要求 Python 3.10+，本次只实测 3.12.14；没有验证所有宿主/系统组合。
未证明宿主新会话自动加载；未运行真实 Trivy/Lynis、真实服务器扫描、红队操作，
未创建凭据或调整网络配置。安装脚本的存在不能代表授权或工具扫描结果。

## 实施方法

使用本机 Superpowers A0/A18 7.0.0 profile 与 STS 0.2.5 thin adaptation：
已批准范围 → 短计划 → 参考缺失基线与行为 RED → 实现/GREEN → 一次独立
消费兼分支审阅 → 针对性收尾。没有另起方案探索或重复审查层。
SP 部分 shell helper 含 CRLF，原调用实际失败；仅在临时副本转换换行后使用，
本机 SP/STS 文件保持原样。独立 clone 满足隔离要求；最终分支交由主控推送，
不合并。远端发布状态以最终交付消息为准。
