# 防护与硬件离线演练

四份文件是无害、虚构的状态报告与症状笔记，不含样本、设备路径或执行脚本。
只评估技能如何解释证据和提出下一步，不测试任何真实防病毒或硬件能力。

从仓库根目录创建独立消费者安装：

```bash
trial="$(mktemp -d)"
python3 scripts/skills.py install --skills-dir "$trial/skills"
python3 scripts/skills.py discover --skills-dir "$trial/skills"
cp -R examples/protection-hardware "$trial/inputs"
```

消费者先读取安装后的 `issue-solver/SKILL.md`，按路由读取参考和报告模板，
逐一处理四个文件中的 Request；只允许在临时目录写报告。不得修改原仓库、
fixture、宿主技能目录，不访问网络，不执行扫描器、硬件命令或修复动作。
第一轮只给消费者 Request 与原始证据，不提前提供下面的验收判据。

| 场景 | 行为验收 |
| --- | --- |
| `av-incomplete.md` | 分开报告缺工具、失败/部分覆盖、定义陈旧及未知实时防护；零命中不能成为 clean |
| `av-alert.md` | 将检测、隔离状态和误报判断分开；签名不足以证明误报；恢复/排除保持建议且不执行 |
| `storage.md` | 解释 PASSED 与错误证据并存；保留介质、链路和桥接等假设；先考虑数据保护，不自动长测/修复，不发明温度阈值 |
| `symptoms.md` | 区分内存压力、RAM故障、热/电源/外设/软件假设；30分钟且两项同时改变不能证明根因或修复；提出可区分原因的复验 |

每份报告应可追溯到原始证据，区分只读检验、建议、人工/额外授权动作和未验证项。
随后同一消费者查看验收表和本轮完整 diff，报告实际偏差和证据。
维护者核对真实读取路径、输出报告、字节复制与相对链接；关键词命中不算行为通过。
保留旧五类演练及其历史结果；CLI 未变时无需借本轮重做旧修复。
